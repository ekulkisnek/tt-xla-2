# How to Run Your Own Prompts with Tensor Parallel Qwen

## Quick Start

### Option 1: Command Line (Single Prompt)

Run a single prompt directly from the command line:

```bash
# Tensor Parallel (TP=2) - Default
python interactive_generation.py --prompt "The capital of France is" --max-tokens 20

# Single Device
python interactive_generation.py --prompt "The capital of France is" --mode single --max-tokens 20

# Tensor Parallel with 4 devices
python interactive_generation.py --prompt "The capital of France is" --mode tp4 --max-tokens 20

# Compare parity between single and TP
python interactive_generation.py --prompt "The capital of France is" --mode compare --max-tokens 10
```

### Option 2: Interactive Mode

Start interactive mode to enter multiple prompts:

```bash
python interactive_generation.py --interactive
```

Then enter prompts interactively:
```
Enter your prompt: The capital of France is
Max tokens to generate (default 15): 20
Temperature 0.0-1.0 (default 0.8): 0.8
Mode - single/tp2/tp4/compare (default tp2): tp2
```

## Examples

### Basic Usage
```bash
# Generate text with your prompt
python interactive_generation.py --prompt "Once upon a time"

# More creative generation (higher temperature)
python interactive_generation.py --prompt "In a galaxy far away" --temperature 1.0 --max-tokens 25

# Deterministic generation (temperature 0)
python interactive_generation.py --prompt "To be or not to be" --temperature 0.0
```

### Testing Different Modes

```bash
# Compare single vs tensor parallel
python interactive_generation.py --prompt "Hello world" --mode compare

# Test scaling with TP=4
python interactive_generation.py --prompt "The quick brown fox" --mode tp4

# Single device for baseline
python interactive_generation.py --prompt "Machine learning is" --mode single
```

## Command Line Options

- `--prompt`: Your text prompt (required unless using --interactive)
- `--max-tokens`: Maximum number of tokens to generate (default: 15)
- `--temperature`: Generation temperature 0.0-1.0 (default: 0.8)
  - 0.0 = deterministic (always picks most likely token)
  - 1.0 = more creative/random
- `--mode`: Generation mode
  - `single`: Single device
  - `tp2`: Tensor parallel with 2 devices (default)
  - `tp4`: Tensor parallel with 4 devices  
  - `compare`: Compare single vs TP=2 for parity
- `--interactive`: Start interactive mode

## Understanding the Output

The script shows several pieces of information:

1. **Input tokens**: How your text was tokenized (for debugging)
2. **Generated tokens**: The raw token IDs generated by the model
3. **Generated text**: Approximate conversion back to text (basic detokenization)
4. **Performance**: Generation time and tokens per second
5. **Parity check**: When using compare mode, verifies single device and TP produce identical outputs

## Notes

### Tokenization
- This demo uses a simple character-based tokenizer for demonstration
- In production, you'd use a proper tokenizer (like tiktoken or sentencepiece)
- Letters become tokens 3-28, digits 29-38, punctuation 39-44
- Unknown characters get mapped to higher token IDs

### Model Configuration
- The demo model has 256 hidden size, 6 layers, ~4.5M parameters
- This is much smaller than the full Qwen 2.5-7B for faster testing
- The tensor parallel implementation scales to any model size

### Performance
- Virtual CPU performance is slower than real GPUs
- On real hardware, TP should show significant speedups
- The important thing is that functionality and parity are perfect

## Troubleshooting

If you get errors:
1. Make sure you're in the correct directory: `tt-xla-tests/tests/jax/models/qwen25/tp_workdir/stage3/`
2. The JAX environment is set up automatically by the script
3. All dependencies should be available since the tests passed

## What's Happening Under the Hood

1. **Tokenization**: Your text is converted to token IDs
2. **Model Setup**: The tensor parallel model is initialized with proper sharding
3. **Generation**: The model generates tokens one by one using the KV-cache
4. **Detokenization**: Tokens are converted back to approximate text

The tensor parallel implementation:
- Shards attention and MLP weights across devices
- Uses psum operations for all-reduce where needed
- Maintains perfect parity with single device mode
- Supports incremental generation with KV-cache
